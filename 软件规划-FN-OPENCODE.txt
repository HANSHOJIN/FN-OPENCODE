# 二、核心架构

不要把 OpenCode Desktop / AppImage / Electron/Tauri 桌面程序直接塞进 fnOS。

推荐架构：

```text
fnOS
│
├─ OpenCode FPK
│
├─ OpenCode Linux CLI / Server Binary
│      ↓
│  opencode web
│      ↓
│  HTTP Server
│
└─ 飞牛桌面
       ↓
    iframe / 内嵌窗口
       ↓
    OpenCode Web UI
```

核心思路：

- fnOS 自己承担“桌面窗口壳”
- OpenCode 只负责 Web Server + Web UI
- 不再套一层桌面应用

# 五、第一版不要优先上飞牛统一网关

飞牛统一网关理论上更优雅：

```text
fnOS 登录
↓
/app/opencode
↓
OpenCode
```

但是 OpenCode Web UI 需要验证是否完整支持 subpath/basePath。

OpenCode 当前很多前端/API 路径可能使用根路径：

```text
/_assets/...
/global/event
/session/...
```

如果直接挂载：

```text
/app/opencode
```

可能导致：

```text
/app/opencode/_assets
```

与：

```text
/_assets
```

不兼容。

因此：

## 第一版优先方案

使用：

```text
http://NAS_IP:4096/
```

然后由飞牛桌面 iframe 打开这个端口。

优点：

- 少一层代理
- SSE 更稳定
- WebSocket/stream 问题更少
- OpenCode 无需 patch basePath
- 更容易先做出可用版本

## 第二阶段

如果确认 OpenCode 支持 basePath，或者我们能非常轻量地做代理适配，再研究：

```text
/app/opencode
```

以及飞牛统一登录态。

# 九、OpenCode HOME / XDG 隔离

OpenCode 不应该污染 fnOS 系统用户 Home。

启动时设置独立环境。

建议：

```bash
export HOME="$TRIM_PKGHOME"

export XDG_CONFIG_HOME="$TRIM_PKGETC"
export XDG_DATA_HOME="$TRIM_PKGVAR/data"
export XDG_CACHE_HOME="$TRIM_PKGVAR/cache"
export XDG_STATE_HOME="$TRIM_PKGVAR/state"
```

具体变量要结合 OpenCode 实际使用路径验证。

然后执行：

```bash
"$TRIM_APPDEST/bin/opencode" web ...
```

目标：

OpenCode 的：

- 配置
- Provider
- Session
- DB
- Cache
- Plugin
- Logs

都留在 FPK 管理范围。

升级 FPK 后不要丢配置。

# 三十四、最终产品体验

最终想要的是：

```text
飞牛用户
↓
下载 OpenCode.fpk
↓
安装
↓
飞牛桌面出现 OpenCode
↓
双击
↓
窗口打开
↓
选择模型
↓
打开项目
↓
直接让 AI 写代码
```

而不是：

```text
SSH
Docker
命令行
Node
npm
手动启动 server
浏览器输入端口
```

产品必须面向普通飞牛用户。

# 三十五、核心设计原则

一句话：

> 把 OpenCode 做成真正的飞牛原生应用，而不是“在 NAS 上跑了一个 OpenCode Server”。

用户不应该感觉自己在维护服务器。

他只应该感觉：

> “我的飞牛桌面里多了一个 OpenCode。”
```
